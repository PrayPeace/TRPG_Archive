# 실제 환경 시험 절차 (11-21.25)

자동 시험은 가짜 서버, 가짜 Deepgram, 가짜 녹음기로 돕니다. 아래는 그것으로 알 수 없는 것을 사람이 실제로 재는 순서입니다. **아직 하나도 하지 않았습니다.** 결과 칸은 비어 있고, 채우기 전에는 "통과"라고 적지 않습니다.

모든 시험은 **테스트용 채널**에서 합니다. 질긴 결속에서는 하지 않습니다.

숫자는 설정 탭 → "세션 측정"에서 봅니다. 이 기기에서만 세고 서버에 보내지 않으며 요금이 들지 않습니다. 시험 전에 [새로 재기], 끝나면 [복사].

---

## 1. 실제 음성 끊김 시험 (PC 크롬, 15분쯤)

준비: 테스트용 채널에 들어가 받아쓰기를 켭니다. 책이나 기사를 소리 내어 읽습니다. 끊는 동안에도 계속 읽고, 끊은 시각과 그때 읽던 문장을 종이에 적어 둡니다.

끊는 방법은 와이파이를 끄는 것입니다. (크롬 개발자 도구의 Offline은 이미 열린 Deepgram 연결을 끊지 않아서 쓸 수 없습니다.)

| 끊은 시간 | 설계상 기대 | 실제: 끊긴 동안 읽은 문장 중 적힌 비율 | 실제: "※ 받아쓰기 끊김" 줄의 초 | 같은 문장이 두 번 적혔나 | 다시 적히기까지 걸린 시간 |
|---|---|---|---|---|---|
| 2초 | 끊김을 못 느끼고 지나가거나, 몇 초짜리 구간이 설정 탭에 남음 | | | | |
| 20초 | 다시 연결된 뒤 끊긴 동안의 말이 적힘. 끊긴 것을 알아채기 전 몇 초는 빠질 수 있고 그만큼 구간으로 남음 | | | | |
| 60초 | 위와 같음. 모아 둔 소리를 약 2.5배 빠르기로 보내므로 다 적히기까지 25초쯤 | | | | |
| 90초 | 경계. 다 적히거나, 90초를 넘겨 앞부분이 버려짐 | | | | |
| 120초 | 앞의 약 90초는 버려지고 "※ 받아쓰기 끊김 약 1분 30초" 줄이 남음. 마지막 약 30초만 적힘 | | | | |

같이 볼 것:
- 세션 측정의 "끊긴 동안의 소리 이어 보내기 시도 N번(초)"과 "Deepgram이 끝까지 처리했다고 확인 N번(초)"이 같은지. 다르면 Deepgram이 빠르게 보낸 소리를 다 받아 적지 못한 것입니다.
- "(확정 전)"이 붙은 줄이 몇 줄인지, 그 줄의 글이 실제로 한 말과 맞는지.
- 받아쓰기를 끈 직후의 마지막 한두 낱말이 적혔는지 (말하다가 바로 끄기를 5번).
- 휴대폰에서도 20초, 120초를 한 번씩. 화면을 끄면 브라우저가 마이크를 멈추므로 화면은 켜 둡니다.

**이 시험으로 확인하려는 미검증 가정**
1. Deepgram이 새 연결에서 실제 시간보다 빨리 들어오는 소리를 정상으로 받아 적는다.
2. Deepgram이 조용할 때도 결과를 보내서 "어디까지 들었는지"를 알 수 있다.
3. 끊김을 알아채는 데 걸리는 시간이 5~8초 이내다.

## 2. 대기열 시험 (PC 크롬, 10분쯤)

| 시험 | 방법 | 기대 | 실제 |
|---|---|---|---|
| 탭 강제 종료 | 와이파이를 끄고 10줄 말한 뒤 작업 관리자로 크롬을 끝냄. 다시 열고 와이파이를 켬 | 10줄이 모두 저장됨, 중복 0 | |

| 다른 방 | 와이파이를 끄고 테스트용 채널에서 5줄 말한 뒤 다른 방으로 옮김. 와이파이를 켬 | 설정 탭에 "다른 방에 못 보낸 말"이 보이고 저절로 보내짐 | |

## 4. 실제 세션 측정 (5명, 3~4시간)

추가 요금 없이 잽니다. Deepgram과 Claude는 평소 쓰는 만큼만 씁니다.

**시작 전**
- 모두 설정 탭 → 세션 측정 → [새로 재기].
- 마스터는 시작 시각을 적습니다.

**하는 동안 (평소대로 플레이)**
- 프로그램 때문에 진행이 멈춘 일이 있으면 마스터가 시각과 이유를 한 줄 적습니다. (예: 21:40 받아쓰기 다시 켬, 30초)

**끝난 뒤**
- 모두 세션 측정 [복사]해서 보냅니다.
- 마스터는 진단 화면을 찍습니다.
- 아래 다섯 가지를 각자 1~5점으로 답합니다.

| 숫자 | 어디서 | 목표(제안) |
|---|---|---|
| 서버 저장 확인 ÷ 기기에 넣은 줄 | 세션 측정 [받아쓰기] | 100% |
| 서버가 거른 중복 | 〃 | 기록만 |
| 연결 끊김 횟수, 누락 가능 구간 합계 초 | 세션 측정 [끊김] | 3시간에 60초 이하 |
| 이어 보내기 시도 대비 Deepgram 확인 | 〃 | 같아야 함 |
| 저장까지 걸린 시간 중간, 느린 5% | 세션 측정 | 중간 5초 이하 |
| 끝났을 때 못 보낸 말, 저장 못 한 말 | 세션 측정 [지금 남은 것] | 0 |
| 다음 할 일: 연 횟수, 바로 보이는 부분이 뜨기까지, AI 추천이 뜨기까지, "그 뒤 새 기록 있음"이 뜬 채로 본 횟수 | 세션 측정 [다음 할 일] | 바로 보이는 부분 1초 이하 |
| 지금 장면: 연 횟수, 장면 추정을 손으로 고친 횟수, AI 없이 판정 찾기 대 AI로 묻기 | 세션 측정 [지금 장면] | 고친 횟수 ÷ 연 횟수가 낮을수록 좋음 |
| 프로그램 때문에 진행이 멈춘 횟수와 합계 시간 | 마스터 메모 | 3회, 3분 이하 |
| 요약이 끝난 곳 = 대화 줄 수 | 마스터 진단 | 같아야 함 |

**설문 (1 전혀 아니다 ~ 5 매우 그렇다)**
1. 이 프로그램 덕분에 메모를 덜 해도 됐다.
2. 화면을 보느라 대화를 놓친 적이 있다. (거꾸로 문항)
3. 다음 할 일 추천이 지금 상황에 맞았다.
4. (마스터) 지금 장면이 실제 장면과 맞았다.
5. 다음 세션에도 쓰고 싶다.

요약과 실제 있었던 일의 차이는 세션 뒤 마스터가 요약을 읽으며 틀린 줄, 빠진 중요한 일, 지어낸 일의 수를 셉니다. `tests/quality/README.md`의 항목 이름을 그대로 씁니다.
