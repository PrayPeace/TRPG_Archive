# 실제 환경 시험 체크리스트 (11-21.26)

자동 시험은 가짜 서버, 가짜 Deepgram, 가짜 녹음기로 돕니다. 아래는 그것으로 알 수 없는 것을 사람이 실제로 재는 순서입니다. **아직 하나도 하지 않았습니다.** 결과 칸은 비어 있고, 채우기 전에는 "통과"라고 적지 않습니다.

모든 시험은 **테스트용 채널**에서 합니다. 질긴 결속에서는 하지 않습니다.

숫자는 설정 탭 → "세션 측정"에서 봅니다. 이 기기에서만 세고 서버에 보내지 않으며 요금이 들지 않습니다. 시험 전에 [새로 재기], 끝나면 [복사].

**순서** (앞 단계가 끝나야 다음 단계로)

- [ ] 0단계. PC에서 자동 배포 연결, 테스트용 채널에 새 판 올리기 (`엔진_자동배포_설정.md` A~C)
- [ ] 1단계. 테스트용 채널에서 혼자 받아쓰기 10분: 말한 것이 적히고 "모두 저장됨"이 뜨는지
- [ ] 2단계. 인터넷 끊기와 다시 잇기 (아래 1, 2)
- [ ] 3단계. 배포 되돌리기 (아래 3)
- [ ] 4단계. 두 사람 모의 세션 30분: 동시에 말하기, 한 사람이 새로 고침, 한 사람이 탭 두 개
- [ ] 5단계. AI 품질 (`tests/quality/README.md`, 새로 만든 연습 방에서)
- [ ] 6단계. 질긴 결속에 올리기 (`엔진_자동배포_설정.md` D)
- [ ] 7단계. 실제 5인 세션 (아래 4)
- [ ] 8단계. 세션 측정과 설문을 모아 다음에 고칠 것 정하기

## 1. 실제 음성 끊김 시험 (PC 크롬, 15분쯤)

준비: 테스트용 채널에 들어가 받아쓰기를 켭니다. 책이나 기사를 소리 내어 읽습니다. 끊는 동안에도 계속 읽고, 끊은 시각과 그때 읽던 문장을 종이에 적어 둡니다.

끊는 방법은 와이파이를 끄는 것입니다. (크롬 개발자 도구의 Offline은 이미 열린 Deepgram 연결을 끊지 않아서 쓸 수 없습니다.)

| 끊은 시간 | 설계상 기대 | 실제: 끊긴 동안 읽은 문장 중 적힌 비율 | 실제: "※ 받아쓰기 끊김" 줄의 초 | 같은 문장이 두 번 적혔나 | 다시 적히기까지 걸린 시간 |
|---|---|---|---|---|---|
| 2초 | 끊김을 못 느끼고 지나가거나, 몇 초짜리 구간이 설정 탭에 남음 | | | | |
| 20초 | 다시 연결된 뒤 끊긴 동안의 말이 적힘. 끊긴 것을 알아채기 전 몇 초는 빠질 수 있고 그만큼 구간으로 남음 | | | | |
| 60초 | 위와 같음. 모아 둔 소리를 약 2.5배 빠르기로 보내므로 다 적히기까지 25초쯤 | | | | |
| 90초 | 경계. 다 적히거나, 90초를 넘겨 앞부분이 버려짐 | | | | |
| 120초 | 60초쯤부터 화면에 "90초를 넘기면 되살리지 못해요" 안내가 뜸. 앞의 약 90초는 버려지고 "※ 받아쓰기 끊김 약 1분 30초" 줄이 남음. 마지막 약 30초만 적힘 | | | | |

같이 볼 것:
- 세션 측정의 "끊긴 동안의 소리 이어 보내기 시도 N번(초)"과 "Deepgram이 그 소리의 끝 위치까지 처리했다고 알림 N번(초)"이 같은지. 다르면 Deepgram이 빠르게 보낸 소리를 다 처리하지 못한 것입니다.
- 위 숫자가 같아도 글이 맞게 적혔다는 뜻은 아닙니다. 끊긴 동안 읽은 문장을 대화 탭의 글과 한 줄씩 맞춰 봅니다 (표의 "적힌 비율").
- "(확정 전)"이 붙은 줄이 몇 줄인지, 그 줄의 글이 실제로 한 말과 맞는지.
- 받아쓰기를 끈 직후의 마지막 한두 낱말이 적혔는지 (말하다가 바로 끄기를 5번). 세션 측정 [끄기] 줄의 "종료 신호 보내기 실패", "2초 뒤 닫음", "보내지 못한 소리 조각"이 0인지.
- 아무 말 없이 10초 켰다가 끄기를 3번: "※ 받아쓰기 끊김 … 끌 때 받아 적혔는지 확인 못 함" 줄이 **생기지 않아야** 합니다. 생기면 Deepgram이 조용할 때 처리 위치를 알려 주지 않는다는 뜻이니 알려 주세요 (미검증 가정 2번).
- 끄자마자 다시 켜기를 3번: 끄기 직전의 말이 한 번만 적히고(두 번 적히지 않고), 다시 켠 뒤의 말이 정상으로 적히는지.
- 같은 문장을 두 번 이어 말하기("문을 연다. 문을 연다.")를 3번: 두 번 다 적히는지. 세션 측정의 "확정한 곳과 겹쳐 온 결과" 숫자도 적어 둡니다.
- 휴대폰에서도 20초, 120초를 한 번씩. 화면을 끄면 브라우저가 마이크를 멈추므로 화면은 켜 둡니다.

**이 시험으로 확인하려는 미검증 가정**
1. Deepgram이 새 연결에서 실제 시간보다 빨리 들어오는 소리를 정상으로 받아 적는다.
2. Deepgram이 조용할 때도 결과를 보내서 "어디까지 들었는지"를 알 수 있다.
3. 끊김을 알아채는 데 걸리는 시간이 5~8초 이내다.

## 2. 대기열 시험 (PC 크롬, 10분쯤)

| 시험 | 방법 | 기대 | 실제 |
|---|---|---|---|
| 탭 강제 종료 | 와이파이를 끄고 10줄 말한 뒤 작업 관리자로 크롬을 끝냄. 다시 열고 와이파이를 켬 | 10줄이 모두 저장됨, 중복 0 | |
| 탭 두 개 | 같은 방을 탭 두 개로 열고 와이파이를 끈 채 양쪽에서 채팅 5줄씩. 와이파이를 켬 | 10줄 모두 저장, 중복 0. 두 탭 모두 "모두 저장됨" | |
| 탭 두 개 + 닫기 | 위와 같이 하되 와이파이를 켜기 전에 한 탭을 닫고 2분 기다림 | 남은 탭이 닫힌 탭의 말까지 보냄. 10줄 저장, 중복 0 | |
| 다른 방 | 와이파이를 끄고 테스트용 채널에서 5줄 말한 뒤 다른 방으로 옮김. 와이파이를 켬 | 설정 탭에 "다른 방에 못 보낸 말"이 보이고 저절로 보내짐 | |

## 3. 배포 되돌리기 시험 (GitHub Actions)

`엔진_자동배포_설정.md`의 C를 그대로 합니다. 추가로 기록할 것:

| 항목 | 기대 | 실제 |
|---|---|---|
| `check`가 운영 방의 웹 앱 버전과 자동 정리(HEAD) 버전을 따로 읽음 | 기록에 "운영 방 N: 자동 정리 라이브러리 … · 웹 앱 방 버전 … · /exec …" 줄 | |
| `drill`이 서로 다른 판을 오감 | "서로 다른 판을 오가며 대화 유지" | |
| `clasp pull --versionNumber`가 예전 방 버전의 매니페스트를 읽어 옴 | 오류 없음 | |
| `clasp deployments` 출력에서 배포가 가리키는 버전을 읽음 | "@숫자"가 기록에 보임 | |
| 되돌림표 줄이 기록과 release-state 파일에 남음 (방 번호가 아니라 `r` + 8글자 식별값으로) | 예 | |
| `restore`에 그 줄을 넣으면 그 상태로 돌아감 | "/exec … 확인"과 방별 결과가 기록에 보임 | |
| target을 일부러 틀리게(`prod`) 해서 연습 방 되돌림표를 넣음 | "지금 방 목록에 없어요 … 아무 방도 바꾸지 않았어요"로 멈춤 | |
| 같은 되돌림표로 `restore`를 한 번 더 | "이미 되돌림표의 상태예요. 바꾸지 않아요" | |
| 되돌린 5분 뒤 테스트용 채널 진단의 자동 정리 판 | 되돌린 판과 같음 | |
| check의 "엔진 주소로 직접 도는 방" 줄 | "없음" 또는 "웹 앱으로 답하는 배포가 없어요" | |

## 4. 실제 세션 측정 (5명, 3~4시간)

추가 요금 없이 잽니다. Deepgram과 Claude는 평소 쓰는 만큼만 씁니다.

**시작 전**
- 모두 설정 탭 → 세션 측정 → [새로 재기].
- 마스터는 시작 시각을 적습니다.

**하는 동안 (평소대로 플레이)**
- 프로그램 때문에 진행이 멈춘 일이 있으면 마스터가 시각과 이유를 한 줄 적습니다. (예: 21:40 받아쓰기 다시 켬, 30초)

**끝난 뒤**
- 모두 세션 측정 [복사]해서 보냅니다.
- 마스터는 진단 화면을 찍습니다.
- 아래 일곱 가지를 각자 1~5점으로 답합니다.

| 숫자 | 어디서 | 합격 기준 |
|---|---|---|
| 이 창이 받아 적은 줄 = 서버 보존 확인(새로 저장 + 이미 있었음) + 서버가 버림·거절 | 세션 측정 [기록 보존], 사람마다 | 빠진 줄 0 |
| 같은 발언이 대화에 두 번 저장됨 | 마스터가 대화 탭에서 확인 | 0건 |
| 끝났을 때 못 보낸 말, 저장 못 한 말, 메모리에만 있는 말 | 세션 측정 [지금 남은 것] | 모두 0 |
| 연결 끊김 횟수, 누락 가능 구간 합계 초 | 세션 측정 [끊김] | 기록만 (그림자 녹음기를 넣을지 정하는 근거) |
| 이어 보내기 시도 대비 Deepgram 처리 알림 | 〃 | 같아야 함 |
| 저장까지 걸린 시간 | 세션 측정 | 중간 5초 이하, 느린 5% 10초 이하 |
| ① 지금 상황이 화면에 뜨기까지 | 세션 측정 [다음 할 일] | 1초 이내 |
| 지금 장면이 화면에 뜨기까지 | 세션 측정 [지금 장면] | 3초 이내 |
| 판정 결과 찾기 (AI 없이) | 마스터가 초시계로 3번 | 5초 이내 |
| "그 뒤 새 기록 있음"이 뜬 채로 본 횟수, 다시 추천 횟수 | 세션 측정 [다음 할 일] | 기록만 |
| 장면 추정을 손으로 고친 횟수 ÷ 지금 장면을 연 횟수 | 세션 측정 [지금 장면] | 기록만 (낮을수록 좋음) |
| 요약에서 빠진 핵심 단서 | 세션 뒤 마스터가 요약을 읽으며 | 0건 |
| 마스터 전용 자료가 공개 화면에 보임 | 세션 뒤 마스터가 요약·정리·다음 할 일·내보낸 파일 확인 | 0건 |
| 프로그램 때문에 진행이 멈춘 횟수와 합계 시간 | 마스터 메모 | 0건이 목표 (있으면 시각과 이유를 적음) |
| 요약이 끝난 곳 = 대화 줄 수 | 마스터 진단 | 같아야 함 |

숫자를 읽을 때:
- 세션 측정은 기기마다, 탭마다 따로 셉니다. 한 사람이 탭을 두 개 열었으면 두 탭의 것을 모두 보냅니다.
- 창을 새로 고친 뒤 보낸 말은 "이어받아 보낸 말"로 세어집니다. 그래서 새로 고친 사람은 "받아 적은 줄"과 "보존 확인"이 맞지 않을 수 있고, 그때는 [지금 남은 것]이 0인지로 판단합니다.
- "화면에 뜨기까지"는 누른 뒤 화면에 그려질 때까지입니다. 읽고 이해하는 데 걸린 시간은 기계가 재지 못해서 아래 설문 6번으로 묻습니다.
- 저장 시간의 중간·느린 5%는 최근 3,000줄 표본이고, 평균·최대는 전체입니다. 측정 글에 그렇게 적혀 나옵니다.

**설문 (1 전혀 아니다 ~ 5 매우 그렇다)**
1. 이 프로그램 덕분에 메모를 덜 해도 됐다.
2. 화면을 보느라 대화를 놓친 적이 있다. (거꾸로 문항)
3. 다음 할 일 추천이 지금 상황에 맞았다.
4. (마스터) 지금 장면이 실제 장면과 맞았다.
5. 다음 세션에도 쓰고 싶다. (목표: 평균 4.5 이상)
6. 화면을 잠깐(5초쯤) 보는 것만으로 지금 상황과 다음에 할 일을 알 수 있었다.
7. 문제가 생겼을 때(끊김, 느림) 세션은 그대로 이어 갈 수 있었다.

요약과 실제 있었던 일의 차이는 세션 뒤 마스터가 요약을 읽으며 틀린 줄, 빠진 중요한 일, 지어낸 일의 수를 셉니다. `tests/quality/README.md`의 항목 이름을 그대로 씁니다.
