# AI 품질 시험 자료

요약·정리·다음 할 일을 만드는 AI가 "틀리게 적는 일"을 얼마나 하는지 재는 자료입니다.

**지금까지 실제 Claude로 돌린 적이 없습니다.** 저장소의 자동 시험(`tests/t_quality.js`)은 채점 도구가 맞게 세는지만 봅니다. 사람이 쓴 "잘한 답"과 "틀린 답"을 넣어 본 것이고, AI 품질 점수가 아닙니다.

## 들어 있는 것

| 파일 | 내용 |
|---|---|
| `fixture.js` | 대본(세션 1, 세션 2), 마스터 전용 자료(`keeperOnly`), 정답표(`key`) |
| `score.js` | 정답표와 비교해 숫자를 내는 채점 도구 |
| `run-real.js` | 연습 방에 대본을 넣고 실제 요약·추천을 받아 채점까지 하는 도구 |

## 대본에 넣은 함정

- 농담("불 지르고 가자"), 가정("만약에 집사를 묶으면"), 게임 밖 잡담(다음 주 약속)
- 판정 성공과 실패가 섞여 있음 (심리학 실패, 도서관 이용 실패, 관찰력 성공, 듣기 성공)
- NPC의 거짓말일 수 있는 주장 ("서재에 들어간 적이 없습니다")
- 플레이어의 추측 ("내 생각엔 집사가 범인")
- 장면 전환 (현관 → 서재 → 지하실 계단, 지나가며 말만 한 장소도 있음)
- 받아쓰기 인식 오류 (집싸, 도서간, 벽날로)
- 복구된 말 표시 "(확정 전)"과 "※ 받아쓰기 끊김 …" 안내 줄
- 세션 1에서 이미 끝난 일 (다시 추천하면 안 됨)
- 마스터 전용 자료에만 있는 사실 (공용 화면에 나오면 누출)

## 재는 숫자와 합격선

| 항목 | 합격선 |
|---|---|
| 핵심 단서 누락 (5개: 헐거운 벽돌, 찢어진 일기, 없는 마지막 장, "지하에 가두었다", 쇠사슬 소리) | 0 |
| 부가 정보 누락 (3개: 집사의 주장, 계단 앞까지 감, 주인이 여행 중이라는 말) | 1 이하 |
| 지어낸 사실·농담·가정을 사건으로 적음 | 0 |
| 판정 성공/실패 뒤바뀜 | 0 |
| NPC 주장을 사실처럼 적음 | 0 |
| 플레이어 추측을 사실처럼 적음 | 0 |
| 추천을 만들었나 | 예 (못 만들면 다른 항목이 좋아도 불합격) |
| 이미 끝난 일을 다시 추천 | 0 |
| 지금 장면이 맞음 | 예 |
| 하기로 한 일이 맨 위에 있음, 있어야 할 추천이 빠지지 않음 | 모두 |
| 마스터 자료 누출 | 0. 마스터 자료가 방에 올라가 있었는지 확인하지 못했으면 "확인 못 함" |
| 판정 빠짐, 받아쓰기 안내를 요약에 옮김, 잘못 들린 낱말을 그대로 적음 | 숫자만 기록 |

판정은 셋 중 하나로 나옵니다.

- **불합격**: 위 합격선을 하나라도 어김.
- **미확인**: 어긴 것은 없지만 확인하지 못한 항목이 있음 (마스터 자료 등록을 확인 못 함, 앞선 시험 기록이 섞인 방에서 돌림). 합격이 아닙니다.
- **자동 채점 합격**: 어긴 것도, 확인 못 한 것도 없음.

자동 채점은 정규식으로 낱말이 있는지만 봅니다. 낱말은 맞는데 뜻이 틀린 문장은 놓칩니다. 그래서 채점 끝에 나오는 "사람이 읽고 확인할 것"까지 끝나야 합격이라고 말할 수 있습니다.

## 실제로 재는 순서 (PC)

1. **새 연습 방을 만듭니다.** 로비에서 새 방을 만들고 이름에 "테스트"나 "연습"을 넣습니다. 시험할 때마다 새 방을 쓰는 것이 좋습니다. 이미 대화가 있는 방에서 돌리면 예전 요약·정리가 섞여서 판정이 "미확인"이 됩니다. 도구는 기록을 지우지 않습니다.
2. 그 방 마스터 탭의 시나리오 자료에 `fixture.js`의 `keeperOnly` 글을 올립니다. 도구가 서버에 물어서 올라가 있는지 확인합니다.
3. 명령 창에서 실행합니다.
   ```
   ROOM_URL="그 방의 /exec 주소" QUALITY_ROOM_ID="그 주소의 /s/ 와 /exec 사이 글자" ROOM_PW="방 비밀번호" KEEPER_PW="마스터 비밀번호" node tests/quality/run-real.js
   ```
4. 화면에 나온 숫자와 `quality-out.json`을 보관합니다. 새 방 세 곳에서 한 번씩, 모두 세 번 돌려 숫자가 흔들리는 폭도 봅니다.
5. "사람이 읽고 확인할 것"을 직접 읽고 예/아니오를 적습니다.

안전장치: 아래 셋이 모두 맞아야 돌고, 하나라도 어긋나면 방에 아무것도 쓰지 않고 멈춥니다.

- `QUALITY_ROOM_ID`가 `ROOM_URL`의 배포ID와 글자 그대로 같음 (이 방에 대본을 넣어도 된다고 사람이 따로 적어 준 것)
- 방 이름에 "테스트"나 "연습"이 있음
- `PROD_ROOMS`를 함께 주었다면 거기에 든 방이 아님

Claude 호출은 한 번 돌릴 때 요약 2~4번, 정리, 추천 1번 정도입니다. 요금이 듭니다. 질긴 결속에서는 돌리지 마세요.

## 한계

- 대본이 하나뿐이라 이 숫자가 좋아도 다른 시나리오에서 같다는 보장은 없습니다.
- 정답표는 낱말이 들어 있는지를 보는 방식이라, 뜻은 틀렸는데 낱말만 맞는 문장은 놓칩니다. 그래서 사람 확인 목록이 따로 있습니다.

## 가상 캠페인 10세션 (`campaign.js`)

세션 하나짜리 대본으로는 "여러 세션에 걸친 기억"을 잴 수 없어서, 10세션짜리 가상 캠페인을 따로 만들었습니다. 모두 지어낸 자료입니다.

| 파일 | 내용 |
|---|---|
| `campaign.js` | 씨앗이 정해진 생성기. 세션별 대본(모두 250줄 안팎), 정리 AI가 만들었을 법한 NPC·단서 정리(근거 줄 포함), 정답표 |
| `campaign-score.js` | 요약·정리·떡밥 레이더를 정답표와 비교하는 채점 도구 |
| `run-campaign.js` | 연습 방에 10세션을 차례로 넣고 실제 요약을 받아 채점하는 도구 (**아직 돌린 적 없음**) |

정답표에 든 것: 세션마다 나온 NPC, 새로 나온 단서와 풀린 단서, 판정(성공/실패), 함정(농담·가정·게임 밖 잡담), 그리고 떡밥 레이더에 떠야 하는 것과 뜨면 안 되는 것.

- 레이더에 떠야 함: 등대지기 한씨(7세션째 안 나옴), 어부 김돌(4세션째), 항해일지 찢긴 장(8세션째), 젖은 은화(5세션째), 동굴 벽 문양(3세션째)
- 뜨면 안 됨: 매번 나오는 촌장, 2세션 전에 나온 수녀, 풀린 단서 두 개, 지난 세션에 다시 언급된 교회 종, 방금 나온 붉은 원

자동 시험(`tests/t_radar.js`)은 이 대본으로 레이더 규칙과 채점 도구가 맞게 도는지만 봅니다. 실제 Claude의 품질 점수가 아닙니다.

실제로 재려면 PC에서 새 연습 방을 만들고 run-real.js와 같은 방법으로 돌립니다.
```
ROOM_URL="…/exec" QUALITY_ROOM_ID="배포ID" ROOM_PW="방 비밀번호" KEEPER_PW="마스터 비밀번호" node tests/quality/run-campaign.js
```
Claude 호출은 20~40번 정도라 요금이 듭니다. 결과는 `campaign-out.json`에 남습니다.
